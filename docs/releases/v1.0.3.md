# RepoPlane v1.0.3

RepoPlane v1.0.3 makes durable memos and other project records discoverable without loading every
full payload. Agents can issue one bounded lexical query, inspect compact kind-specific results,
and fetch or project only the records and fields they need.

## Highlights

- `project_records(mode=search)` now performs real bounded lexical search instead of behaving like
  an unfiltered list.
- Relevance ordering considers record identity, kind, schema, source, and textual payload values,
  with identity and metadata matches ranked ahead of payload-only matches.
- Search results default to compact kind-specific discovery fields; memo results include a derived
  preview capped at 320 characters.
- Callers can use explicit `payload_fields` when exact stored fields are needed and keep `get` as
  the full-record path.
- The public search contract adds only the `query` field and keeps all 14 tool contracts within the
  existing 34 KiB regression budget.

## What ships

The same 14 typed MCP tools and existing CLI commands ship in both platform archives. The
`project_records` input schema adds an optional `query` string for search mode. Record schemas,
write contracts, and the SQLite storage format are unchanged.

## Safety model

Search remains read-only and bounded by the existing item, byte, and time limits. It searches
textual JSON values but not JSON object keys, returns explicit partial state when a bound is hit,
and does not weaken workspace, authorization, or durable-write boundaries.

## Install or upgrade

Download the Windows or Linux amd64 archive and `SHA256SUMS.txt`, verify the archive hash, and
replace the existing `repoplane` binary on `PATH`. Restart the MCP client once so it starts the
v1.0.3 binary; already-running MCP processes continue using their loaded executable.

## Compatibility

This patch supports Windows amd64 and Linux amd64. It requires no database or configuration
migration and preserves existing record payloads, cursors, and explicit `payload_fields` behavior.
Callers that previously used `mode=search` without `payload_fields` receive compact discovery
payloads by default and should use `get` or request fields explicitly when they need full payloads.

## Verification

The tag commit is required to pass generated-schema drift, fresh package tests, vet/build, the
tracked-tree and complete reachable-history privacy scan, Windows and Ubuntu verification, and the
Linux race job. Release archives are built with `-trimpath`, embed `v1.0.3`, and are verified against
the published lowercase SHA-256 checksum file.

## Known limits

Record search is lexical rather than semantic: it does not expand synonyms or generate embeddings.
Memo previews are derived at read time and capped at 320 characters; callers needing exact or longer
content must request the stored field or fetch the record. The complete tool-contract footprint is
close to its current 34 KiB regression ceiling, so future public schema additions require an
explicit budget decision.
