# RepoPlane v1.0.2

RepoPlane v1.0.2 fixes confirmation-only MCP elicitation for strict clients. Runtime workspace
selection and every other approval-gated local stdio operation now send an unambiguous form request
instead of failing before the user can approve it.

## Highlights

- Confirmation requests explicitly send `mode=form` and an object `requestedSchema`.
- Strict MCP clients can complete approved `runtime_config` workspace changes in the active stdio
  session.
- The shared fix also covers runtime access grants, intention writes, report import, Runner actions,
  cache reuse, external reads, and memory export when they require approval.

## What ships

The same 14 typed tools and existing CLI commands ship in both platform archives. This patch changes
only the common confirmation wire shape; tool names, tool inputs, and durable record formats remain
unchanged.

## Safety model

The fix does not bypass approval. Each mutation remains bound to the exact server-held proposal and
one-time request state, and only an explicit client `accept` completes it. Decline, cancellation,
expiry, replay, and HTTP attempts to acquire local stdio authority still fail closed.

## Install or upgrade

Download the Windows or Linux amd64 archive and `SHA256SUMS.txt`, verify the archive hash, and replace
the existing `repoplane` binary on `PATH`. Restart the MCP client once so it starts the v1.0.2
binary; already-running MCP processes continue using their loaded executable.

## Compatibility

This patch supports Windows amd64 and Linux amd64. It preserves existing v1 SQLite databases,
catalog manifests, CLI options, stdio framing, tool inputs, and runtime configuration semantics. No
database or configuration migration is required.

## Verification

The tag commit is required to pass generated-schema drift, fresh package tests, vet/build, the
tracked-tree and complete reachable-history privacy scan, Windows and Ubuntu verification, and the
Linux race job. Release archives are built with `-trimpath`, embed `v1.0.2`, and are verified against
the published lowercase SHA-256 checksum file.

## Known limits

Clients without MCP elicitation support still cannot complete runtime approval flows and must use
the documented startup pre-registration options where available. Existing runtime source-path,
bounded-read, registered-execution, HTTP authorization, and portable-memory exclusions are
unchanged.
