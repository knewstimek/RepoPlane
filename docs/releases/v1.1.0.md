# RepoPlane v1.1.0

RepoPlane v1.1.0 adds optional structured host background and stable memo topic identities while
improving nested-repository operation. It also ships the guarded catalog-driven release workflow
used to build and publish this version.

## Highlights

- Record host alias, role, OS, environment tier, services, management paths, confirmation time, and
  invalidation condition as an optional typed memo without adding another MCP tool.
- Attach an optional stable `topic_key` to ordinary memos, discover it in compact search results,
  and receive at most three related current topic refs when creating a keyed memo.
- Prevent two current memos from claiming the same `(scope, configuration, topic_key)` atomically;
  update content by ID/revision and supersede before renaming a topic.
- Resolve Runner Git preflight from the execution working directory and discover an unambiguous
  nested repository catalog when no explicit catalog root is configured.
- Diagnose unquoted commas in flow-style YAML values with a targeted quoting hint.
- Dispatch guarded releases through the registered `release.dispatch` catalog capability.

## What ships

The same 14 typed MCP tools ship in the Windows and Linux amd64 archives. `memo_write` gains the
optional `topic_key` input, `project_records` compact memo discovery includes stored topic keys, and
catalog arguments may opt into typed host lookup with `host_ref`. The complete serialized tool
contract is 34,739 bytes and Runner's three-tool contract is 5,345 bytes.

## Safety model

Host facts and topic keys are opt-in. RepoPlane does not probe hosts, infer semantic similarity,
merge conflicting facts, or silently overwrite records. Host lookup is activated only by an
explicit catalog `host_ref`; missing or conflicting context produces informational checks and
warnings rather than making an otherwise valid plan unready. Topic uniqueness is exact and
database-enforced, while topic renames require an explicit supersede followed by create.

Release publication remains approval-gated. The tracked workflow requires a clean main commit with
successful CI, scans the public tree and reachable history, builds only declared targets, verifies
checksums and embedded version metadata, and publishes from this tracked note.

## Install or upgrade

Download the Windows or Linux amd64 archive and `SHA256SUMS.txt`, verify the archive hash, and
replace the existing `repoplane` binary on `PATH`. Restart the MCP client so it loads v1.1.0 and
inherits current host environment settings; already-running MCP processes keep their loaded binary
and environment.

## Compatibility

This minor release supports Windows amd64 and Linux amd64 and does not remove or rename tools.
Existing unkeyed `memo.v1` records and free-form writes retain their behavior. Typed host facts use
`memo.v2`; keyed ordinary memos use `memo.v3`. Durable SQLite records migrate automatically to
schema 2, adding only the current-topic uniqueness index and identity guard. Explicit catalog roots
still override nested fallback discovery.

## Verification

The tag commit is required to pass generated-schema drift, fresh package tests, vet/build, the
tracked-tree and complete reachable-history privacy scan, Windows and Ubuntu verification, and the
Linux race job. Release archives are built with `-trimpath`, embed `v1.1.0`, and are checked against
the published lowercase SHA-256 checksum file before and after publication.

## Known limits

Memo search and related-topic selection remain lexical and exact rather than semantic; callers or
their models choose stable topic keys. Related-topic write hints are capped at three refs, and full
content still requires `project_records(mode=get)` or explicit payload fields. Host facts depend on
caller-provided confirmation time and invalidation conditions and are not refreshed by automatic
network probes. Nested catalog fallback does not recursively merge catalogs: ambiguity remains
unselected until a root is configured explicitly.
