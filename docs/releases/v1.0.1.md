# RepoPlane v1.0.1

RepoPlane v1.0.1 removes the restart-and-edit loop from local MCP work: access, live repository
sources, workspace/state selection, optional HTTP service, and portable durable-memory backup can
now be controlled from the active stdio session with explicit user approval.

## Highlights

- `runtime_config` adds, removes, replaces, or refreshes catalog, candidate, rule, and symbol
  sources and applies the new catalog before switching the complete service bundle.
- The primary workspace and external state directory can be selected at runtime; in-flight calls
  stay on one bundle, active Runner work blocks switching, and external path grants are cleared on
  workspace changes.
- An authenticated HTTP endpoint can be started or stopped from stdio with an ignored local
  profile while the stdio MCP connection remains alive; HTTP principals cannot reconfigure it.
- External parent reads, intention writes, report import, Runner execution, and qualified cache
  reuse use one-time MCP elicitation instead of mandatory enable flags and client restarts.
- `memory_backup` and the matching CLI export/restore commands preserve durable records, full
  revision/import history, and retained Runner streams/artifacts across machine or path resets.

## What ships

All 14 typed tools remain stable in discovery. `runtime_access` manages ephemeral capability/path
leases, `runtime_config` manages live service configuration, and `memory_backup` exports portable
durable memory. Existing CLI/TOML options remain compatible startup pre-registration for unattended
hosts; they are no longer required for normal changes during a local stdio session.

## Safety model

Every runtime configuration mutation is bound to an exact server-held proposal and one user
approval. New service bundles are opened, recovered, and catalog-refreshed before routing changes.
State stays outside the selected workspace, arbitrary commands remain unsupported, HTTP retains
bearer/OAuth scope and audit gates, and remote HTTP calls cannot acquire local stdio authority.

## Install or upgrade

Download the Windows or Linux amd64 archive and `SHA256SUMS.txt`, verify the archive hash, and place
the extracted binary on `PATH`. Install `rg`; Git is optional for history search. Existing Codex
registrations may be simplified to `codex mcp add repoplane -- repoplane`; startup arguments may be
kept as initial values. Restart the MCP client once to load the new binary. Future supported changes
then happen through the running session.

## Compatibility

This patch release supports Windows amd64 and Linux amd64 and keeps existing v1 SQLite records,
catalog manifests, CLI options, stdio framing, and prior tool inputs compatible. It adds one typed
tool and does not require a database migration. The complete 14-tool contract remains inside the
34 KiB regression budget.

## Verification

The tag commit is required to pass generated-schema drift, fresh package tests, vet/build,
registered repository verification, tracked-tree/history privacy checks, Windows and Ubuntu CI,
and the Linux race job. Release archives use `-trimpath`, an injected version, and published SHA-256
checksums.

## Known limits

Portable archives intentionally exclude Codex TOML, HTTP profiles, tokens, audit data, and local
keys; keep those secrets in a separate encrypted backup or password manager. Runtime source paths
remain relative to the selected trusted workspace. Semantic/vector search, arbitrary language
parsing, XML, JSONPath/JMESPath, arbitrary shell execution, and automatic secret redaction of
captured Runner output are not provided.
